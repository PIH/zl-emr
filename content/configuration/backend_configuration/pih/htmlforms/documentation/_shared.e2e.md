## EPLD: what it renders and how each form uses it
Whole block is `ifMode VIEW include=false` (:30): nothing in VIEW. Renders `#who-when-where` with `#who` (provider select `encounterProvider`, default `currentUser`, required, role Consulting Clinician `4f10ad1a-…`, :133), `#where` (`encounterLocation`, default `SessionAttribute:emrContext.sessionLocationId`, tags `Consult Note Location`, :140), `#when` (`encounterDate`, default now, :146), hidden `#invalid-user` (:135). Location is a dropdown of locations carrying the tag; the session location is preselected **only if it carries the tag**, else the select is empty and "Required" fires (htmlformentry EncounterDetailSubmissionElement.java:334-347, 405-436).

## How the five hiv wrapper forms work (hiv-intake, hiv-followup, pmtct-intake, pmtct-followup, eid-followup)
Same skeleton in all five (hiv-followup.xml numbering; pmtct-followup is +1/+2 lines). Only formUuid, encounter type and heading differ. They create the parent encounter; the clinical content lives in standalone `hiv/section-*.xml` forms.
- **ENTER** (`ifMode ENTER`, :9-22): `.htmlform` is `display:none` (:35). On load, `if (!getValue("encounterLocation.value")) { hide #next; show .htmlform } else submitHtmlForm()`. So it **auto-submits when the location select has a value**: a session location with tag `HIV Consult Location` (Klinik Ekstèn or Sante Fanm). Provider/date are not tested: they default (currentUser, now) and travel through EPLD's `beforeSubmit`, which runs after the async login check, i.e. after EPLD's ready handler. Result: an encounter with provider/location/date and no obs, then `goToReturnUrl` appends `encounterId=` and lands on the visit overview (`/pihcore/visit/visit.page?patient=&visit=#/overview`, because `visitNote` is in pih-config-haiti-central.json; CustomAppLoaderFactory.java:216-220; entry links :3414 hiv-followup, :3480 hiv-intake, :3511 pmtct-intake, :3525 pmtct-followup, :3542 eid-followup). The link has no `goToNext`: the user then opens a section from the overview. If the session location lacks the tag the form is shown with Next hidden; Save (`#submit` is a native submit button, `onSubmit="submitHtmlForm()"`) and Cancel (`.cancel`, bound in enterHtmlFormWithStandardUi.gsp:22) work, `setUpNextAndSubmitButtons()` is not called.
- **EDIT** (`ifMode EDIT`, :24-33): shows `.htmlform` (h2 with the encounter-type name, EPLD, Next/Save/Cancel) and calls `setUpNextAndSubmitButtons()`. Next saves, then visit.js:874 `goToNextSection` opens the first section.
- **VIEW**: nothing is rendered (everything under `ifMode VIEW include=false`, :36-51).
- Sections come from `encounterTypeConfig.js` (merged tree :1491-1612) and are opened with `editHtmlFormWithStandardUi.page?...&definitionUiResource=hiv/section-*.xml&returnUrl=<visit.page>?visit=&encounter=&currentSection=<id>` (visit.js:960-970). Order: hiv-intake: section-hiv-history, primaryCareExam, pedsVaccinations, section-hiv-assessment, section-hiv-plan. hiv-followup: section-hiv-state, exam, pedsVaccinations, section-dx (`pihcore-diagnosis`), section-hiv-plan. pmtct-intake: section-pmtct-history, exam, ancVaccinations, section-hiv-assessment, section-hiv-plan. pmtct-followup: section-hiv-state, exam, ancVaccinations, section-dx, section-hiv-plan. eid-followup: section-eid-protection, pedsVaccinations, exam, section-eid-plan. (hiv-intake/-followup also have `versions` 1.0/2.0 entries with no sections: legacy encounters.) Section forms: `ifMode VIEW include=false` block with `setUpNextAndSubmitButtons()` and `#next`/`#submit`/`#cancel`; Save returns to the visit page, Next goes to the next allowed section (`allowedWithContext`), the last section goes to the overview (visit.js:975-979).
- Fixture for a spec: session at Klinik Ekstèn (or Sante Fanm), user with provider account, an active visit; for the "form shown" branch log in at a location without the tag.

## Simple UI facts (from the `vitals_v2.2`, `vitalsInpatient` and `vitalsPregnant` specs)

`enterHtmlFormWithSimpleUi.page` / `editHtmlFormWithSimpleUi.page` show one question per screen, with a breadcrumb navigator.
- The current question is `li.question-legend.focused`; the breadcrumb label can differ from the form's label (e.g. "O2 Sat").
- A forward breadcrumb click is refused while the current question has a field error: fill or clear it first.
- `#encounterLocation select` is preselected with the session location.
