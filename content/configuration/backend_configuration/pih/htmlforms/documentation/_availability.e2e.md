## Shared layers (apply to every row below)

1. **Entry point = visit action** (`visitAction`, extension point `...visitActions`) on the visit page (`/pihcore/visit/visit.page`, because every Haiti profile lists `visitNote`), unless the row says otherwise. Link shapes (`CustomAppLoaderUtil` :553-575): Standard UI `htmlformentryui/htmlform/enterHtmlFormWithStandardUi.page?patientId=<uuid>&visitId=<id>&definitionUiResource=file:configuration/pih/htmlforms/<form>`; Simple UI `enterHtmlFormWithSimpleUi.page` (check-in, lab results). Most Haiti rows append `&returnUrl=/openmrs/pihcore/visit/visit.page?patient=<uuid>&visit=<uuid>#/overview` (`patientVisitsPageWithSpecificVisitUrl`, :219: HIV, PMTCT, EID, NCD, primary care, MCH, mental health, vaccination). Registration actions append `&createVisit=true`. `...WithoutVisit` links (lab results) carry no `visitId`. Home-app and dashboard-action links (hiv-dispensing, dispensing, lab results) are spelled out in the rows.
2. **Component flags.** Two layers: **top level** (`loadAppsAndExtensions` :210-520: `checkIn`, `uhmVitals`/`vitals`, `consult`, `edConsult`, `adt`, `dispensing`/`dispensingForm`, `medicationOrder`, `surgery`, `labResults`, `patientRegistration`, `primaryCare`, `vct`, `socioEconomics`, `mchForms`, `covid19`, `commentForm`, `drugRehab`) and **inside `enablePrograms`** (:4131, called :490, needs `programs`): `hiv`, `hivForms`, `hivIntakeForm`, `pmtct`, `prep`, `exposedInfant`, `mentalHealth`, `ncd` (+ `echocardiogram`), `oncology`, `mch`, `vaccination`, `ovc`. Composition of config files replaces arrays (see Sources).
3. **Country and site branches inside the methods** (all Haiti profiles have `country` = Haiti; `isSite` compares the site string case-insensitively):
   - `enableCheckIn` :635: Haiti and not `HSN_SAINT_MARC` -> **`checkin_v3.5.xml`**; HSN -> `checkin.xml`. (The Sierra Leone maternal check-in is not read.)
   - `enableVitals` :726: Haiti branch = Standard UI, session tag `Vitals Location` only (no `Vitals Inpatient Location` exclusion), no MCH/pregnancy/infant clones; the `else if Haiti` (:804) branch adds only the vitals-trend dashboard widget.
   - `enableMCHForms` :2266: Liberia branch (:2268), **Haiti branch (:2310: only `delivery`)**, final `else` (:2323: `ancIntake`, `ancFollowup`, i.e. SL/default; not Haiti). `obGyn` is a separate `if obgyn` block (:2471) for every country.
   - `enablePrimaryCare` :2909: Haiti branch = the four primary-care forms.
   - `enableMentalHealthForm` :2695: Haiti falls in the final `else` (single form `mentalHealth`; SL and Liberia have their own).
   - `enablePatientRegistration` :1655: insurance widget `if Haiti or Mexico` (:1734); contact widget skipped in Liberia; **`patientRegistration-healthCenter` widget only `Haiti && isSite("CENTRAL")` (:1774)**; check-in widget (:1802) needs `checkIn`, names `checkin.xml`.
   - `enableNCDs` :2116: `&returnUrl` omitted only for Liberia; the Part-1/Part-2 forms are SL-only.
4. **Privilege.** Two checks: the extension's `requiredPrivilege` (framework, against the logged-in user) and `userHasPrivilege(p)` = `typeof user !== 'undefined' && hasMemberWithProperty(user.privileges, 'display', '<p>')` inside `require` (matches by **name** in `user.privileges`, so a role alone does not satisfy it; whether a superuser's list contains every name is unverified, check one visit-page render before relying on it). Rows list both.
5. **Session location tag.** `sessionLocationHasTag(t)` = `typeof sessionLocation !== 'undefined' && hasMemberWithProperty(sessionLocation.tags, 'display', '<t>')`; `sessionLocationDoesNotHaveTag(t)` = same with `!`. The tag is on the location chosen at login. The XML's own `<encounterLocation tags=...>` is a second, separate check on ENTER.
6. **`require` expressions** (`RequireUtil`, master), evaluated on the visit page with `patient`, `visit`, `sessionLocation`, `user`, `encounters` (all the patient's encounters):

| Helper | Expression |
|---|---|
| `retro(P)` (shorthand used in the rows) | `or(and(userHasPrivilege(P), patientHasActiveVisit()), userHasPrivilege('Task: emr.retroConsultNote'), and(userHasPrivilege('Task: emr.retroConsultNoteThisProviderOnly'), patientVisitWithinPastThirtyDays))`; `P` is the row's enter-note privilege |

### Visit-page sections and print templates (`section-*`)

No form includes any `section-*` as a subform (no `<subform path="...section-...">` in the merged directory). Each is a standalone form that `encounterTypeConfig.js` wires into the visit page as the VIEW template (`templateModelUrl`, `getAsHtml.action`) and edit link (pencil, `editHtmlFormWithStandardUi.page?patientId=&visitId=&encounterId=&definitionUiResource=file:configuration/pih/htmlforms/<form>`) of an `encounter-section`, so a section is reachable exactly where a form that creates its parent encounter is, and only in EDIT on that encounter. A column is `yes` if any parent form is offered by that profile. A spec creates the parent encounter over REST and opens the edit URL (`SectionFormPage`), which skips the gating.

## Fixture recipes

- **Standard visit-action form at zl-ci** (`outpatientConsult`, `drugOrder`, `socio-econ`, `vct`, primary care, NCD, mental health, ...): patient with an **active** visit at the session location, session at a location carrying the row's tag, user holding the row's privilege or `Task: emr.retroConsultNote`; the row's patient/visit requirement (dup, age, sex, earlier encounter).
- **HIV-program forms**: not offered at zl-ci. Run against hiv-ci with a session location tagged HIV Consult Location, or open the entry URL directly (skips every gating layer). Satisfy when exercising the gate: hiv-intake: no HIV intake in any earlier visit; pmtct-*: female age >= 10; eid-followup: birthdate less than 24 full months before the visit start; prep-*/vct: no Oncology tag.
- **Program dashboards**: to reach an MCH-dashboard clone, enrol the patient in MCH and use a location tagged `MCH Program Dashboard Location`; for the HIV dashboard the patient's only active enrolment must be HIV.
- **hiv-drug-order-documentation**: needs an existing drug order. Create it over REST (an encounter plus a drug order), then open the EDIT URL on that encounter.
- **checkin.xml**: HSN profile for the real entry; at zl-ci the direct URL `enterHtmlFormWithSimpleUi.page?patientId=<uuid>&visitId=<id>&definitionUiResource=file:configuration/pih/htmlforms/checkin.xml`, or the registration-summary widget's edit link on an existing check-in.
- **cancelAdmission / admissionNote (list entry)**: needs a patient on the awaiting-admission list (ADT module logic, unverified); the visit action needs only the tag and privilege.
- **Sections**: create the parent encounter over REST (type uuid in the visit-page table), open the section's edit URL directly; this skips all gating. Conditional sections (peds, eid-protection, vaccinations) show only when the patient's age at the visit start satisfies the `require` in the table.
- **Unreferenced forms** (see Not reachable): only the direct entry/edit URL exists. `vitalsInpatient` / `vitalsPregnant`: the location select starts empty at Klinik Ekstèn (their tags are absent), so a test picks a location.
